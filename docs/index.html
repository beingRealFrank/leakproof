The holes AI-built apps keep shipping

CRITICALTables without RLS

A Supabase table created without Row Level Security can be read and rewritten by anyone holding the anon key, and that key is in your frontend.

CRITICALSecret keys in the bundle

NEXT_PUBLIC_OPENAI_API_KEY, VITE_STRIPE_SECRET: anything with a public prefix is shipped to every visitor. Someone else then pays your AI bill.

CRITICALAllow-all rules

using (true) policies and Firebase if true rules look like security but let everyone in.

HIGHEndpoints that trust everyone

Server actions and API routes are public URLs. If they don't check who's calling and whether the record is theirs, anyone can curl them.

HIGHUser A sees user B's data

Change an id in the URL, get someone else's invoice. Insecure direct object references are the most common logic hole in generated CRUD code.

HIGHNo rate limits

Unthrottled sign-up, password reset and AI endpoints become an open relay for spam and a surprise bill.

FAQ

Is this a penetration test or a compliance certificate?

No. It's a focused code-and-configuration audit for the holes AI-built apps actually have. If you need a SOC 2 or a formal pentest letter, we're not that.

What stacks do you cover?

Best on JavaScript/TypeScript (Next.js, React + Vite, Remix, SvelteKit, Express) with Supabase, Firebase, Prisma or Drizzle, and on Python (FastAPI, Flask, Django). Ask if you're on something else.

What happens to my code?

It's used only for your audit and deleted when the engagement ends. Our access is read-only; we remove ourselves as a collaborator when done.

What if you find nothing?

Then you get a report that says so, listing exactly what was checked, which is useful in its own right for investors, customers and your own sleep.
